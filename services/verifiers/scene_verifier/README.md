# SceneVerifier

Provides `robonix/service/verifier/verify` to verify planar navigation results using `robonix/system/scene/get_robot_context` from a selected Scene provider.

## File Responsibilities

* `scene_verifier/config.py`: Configuration parsing and finite-number validation.
* `scene_verifier/core.py`: Request parsing, navigation goal parsing, Scene response validation, and spatial checks.
* `scene_verifier/scene_client.py`: Atlas connection to the specified provider, MCP observation, and response decoding.
* `scene_verifier/service.py`: Lifecycle handling, request orchestration, and service entry point.
* `tests/test_verifier.py`: Tests for core logic, response decoding, and request orchestration.
* `scripts/build.sh`: Dependency installation and Verify type generation.
* `scripts/start.sh`: Service startup using the built environment.

## Installation and Build

Place this package at `services/verifiers/scene_verifier/` in the Robonix repository.

Add `"services/verifiers/*"` to the existing `[tool.uv.workspace].members` array in the root `pyproject.toml`. Preserve other workspace members. If an existing `"services/*"` pattern matches the `services/verifiers` grouping directory, adjust that pattern or explicitly list the existing service packages to avoid treating the grouping directory as a workspace package.

Run from the repository root:

```bash
uv lock
rbnx validate services/verifiers/scene_verifier
rbnx build -p services/verifiers/scene_verifier
```

The `verifier_mcp` module is generated by `rbnx codegen --mcp`. It should not be handwritten or downloaded separately.

Scene responses are decoded and validated as JSON objects without importing `semantic_map_mcp`. The decoder accepts structured responses, including a `result` wrapper, and text JSON responses.

Unit tests do not require Atlas, ROS 2, or generated types:

```bash
cd services/verifiers/scene_verifier
python3 -m unittest discover -s tests -v
```

## Webots Deployment

Merge the following configuration into the existing sections of `examples/webots/robonix_manifest.yaml`. Do not create duplicate top-level `system` or `service` keys.

```yaml
system:
  executor:
    verification:
      - target_contract_id: robonix/service/navigation/navigate
        target_provider_id: nav2
        verifier_provider_id: scene_verifier
        verifier_args:
          scene_provider_id: scene
          check_yaw: true

service:
  - name: scene_verifier
    path: ../../services/verifiers/scene_verifier
    config:
      distance_tolerance_m: 0.5
      yaw_tolerance_rad: 0.35
      observation_timeout_s: 5.0
```

Start the deployment using the existing Webots build and boot workflow. The package build command above builds only the verifier.

Setting `check_yaw: true` requires an explicitly provided, valid target orientation. An identity quaternion represents zero yaw and is still checked. Setting `check_yaw: false` skips orientation checks entirely. This option is defined by the verification rule; it does not infer intent from natural language.

These verifier-specific arguments are interpreted by SceneVerifier. Executor forwards them unchanged.

The optional `verifier_args.expected_map_id` must be a non-empty string and can be used to require a specific map identity. When omitted, the verifier only requires Scene to report a non-empty map identity; it does not establish which map the navigation goal originated from.

## Behavior and Limitations

* Supports only planar navigation with `goal.header.frame_id == "map"` and a target z coordinate of zero.
* Missing positions, non-finite numbers, invalid required quaternions, and unsupported coordinate frames are request errors.
* Unknown or stale robot poses, map mismatches, and position or orientation errors outside tolerance return `passed=false`.
* Errors must be strictly below their tolerances. An error equal to its tolerance fails verification.
* Atlas or MCP failures, malformed responses, and invalid parameters raise exceptions, which Executor classifies as verification unavailable.
* Verification does not infer success from `SUCCEEDED` or `accepted` values in `target_output`.
* `map_id` identifies a map, while `frame_id` identifies a coordinate frame. They cannot be compared directly.
* Scene does not currently return an independent `frame_id` for the robot pose. The verifier relies on Scene's map-frame snapshot convention. It cannot detect an incorrect internal coordinate frame or prove that the map has not changed since the goal was created.
* Freshness checks use Scene's `stale` flag rather than comparing host and simulation clocks.
* `observation_timeout_s` bounds asynchronous MCP observation only. Synchronous Atlas SDK calls have no additional deadline imposed here. Executor has a separate 60-second verification deadline, which does not guarantee that an Atlas call inside the verifier finishes within five seconds.
* Verification reads a single snapshot. It does not retry movement, wait for navigation to converge, subscribe to ROS topics, or introduce new public contracts.

## Validation

Run the unit tests before deployment, then verify the integration in an environment with the Robonix toolchain, Atlas, Scene, and Webots.

Inspect runtime logs with:

```bash
rbnx logs -t scene_verifier
rbnx logs -t executor
```

A SceneVerifier log containing the navigation `call_id` and `passed=True` or `passed=False` confirms that verification reached a verdict. Check Executor logs for the corresponding final execution result.

`passed=False` means verification completed and rejected the result. `verification unavailable` means verification could not produce a verdict because of an error.
