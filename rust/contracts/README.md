# Robonix contracts (`rust/contracts`)

**Contract id (`[contract].id`) is the canonical description of a logical interface.**  
Each `.toml` file states *what* is being offered (stable id + version + kind), *which ROS 2 IDL types* carry the bytes, and *which communication shape* applies when that interface is mapped to gRPC.

ROS 2 IDL lives under `robonix-interfaces/lib/**` (`.msg` / `.srv`). Contracts **reference** those paths; they do not duplicate field layouts.

## Layers

| Layer | Role |
|--------|------|
| **This tree** | Abstract interface: id, optional semantics, `[io]` type references, `[mode].type`. |
| **`robonix-interfaces/lib`** | ROS 2 messages and services: concrete schemas and naming (`pkg/msg/Name`, `pkg/srv/Name`). |
| **`ridlc`** | Parses `lib` + resolves types referenced from contracts; emits **`robonix_proto/*.proto`** (per package) and **`robonix_contracts.proto`** (per contract). |
| **`robonix-interfaces/robonix_proto`** | Generated protobuf; **`robonix_contracts.proto`** is the gRPC *facade* for contract ids. |
| **`robonix-interfaces/robonix_iceoryx2_py`** | Optional: ctypes payloads for **messages** from `lib`, generated by `ridlc --lang python` (zero-copy / iceoryx2); **not** driven by contract files. |

## `[io]` references

- **`pkg/msg/Name`** — resolves to the protobuf `message` ridlc already emitted for that ROS msg (same shape as ROS).
- **`pkg/srv/Name`** — resolves to the generated `Name_Request` / `Name_Response` messages. For `[io].input`, ridlc uses **`Name_Request`** as the unary/streaming RPC’s first argument type (see `robonix_contracts.proto` and per-package `*.proto`).
- **`std_msgs/msg/Empty`** — mapped to `google.protobuf.Empty` in gRPC.
- **`primitive/string`** — optional escape: `StringWire` in `robonix_contracts.proto` only if a contract still uses it; prefer **`std_msgs/msg/String`** for string payloads.
- **`protobuf://Package/Type`** — escape hatch to an already-generated protobuf type (e.g. app-specific protos under `rust/proto/`).

## `[mode].type` → gRPC (and ROS mental model)

| `type` | gRPC shape (service method name in `robonix_contracts.proto`) | ROS-oriented reading |
|--------|----------------------------------------------------------------|----------------------|
| `rpc` | Unary `Call(request) returns (response)` | One **service** call (`.srv`-like request/response). |
| `stream_out` | `Stream(request) returns (stream element)` | **Server → client** stream; element type is usually a **msg** (like a typed pub stream). |
| `stream_in` | `Stream(stream element) returns (response)` | **Client → server** stream of **msg** elements, then one response. |

Pure ROS **pub/sub** “input-only” / “output-only” ports are expressed at **registration** (who publishes vs subscribes). The contract’s `[io]` still names the **msg** (or empty / srv types) so gRPC and ROS share the same payload definitions; `stream_out` / `stream_in` describe how that payload is framed on gRPC.

## `robonix_contracts.proto` vs concrete `*Service` (important)

`ridlc --contracts` emits **`package robonix.contracts`** with a **single generic `Stream` RPC per contract** (or `Call` for `rpc` mode). That is the **abstract** surface for ids like `robonix/sys/runtime/pilot`.

**Long-lived processes** (Pilot, Executor, Liaison, …) implement the ROS-derived services in **`lib/<pkg>/srv/*.srv` → `robonix_proto/<pkg>.proto`** (e.g. `PilotService.HandleIntent`, `ExecutorService.Execute`). Those RPCs often wrap the “logical” payload in **`Foo_Request`** (`HandleIntent_Request.intent`, `Execute_Request.batch`, …).

| Contract `[contract].id` | What `[io]` describes (payload-level) | Appears as in `robonix_contracts.proto` | Concrete service in generated `*.proto` |
|---------------------------|----------------------------------------|------------------------------------------|-----------------------------------------|
| `robonix/sys/runtime/pilot` | `Intent` → stream `PilotEvent` | `Stream(Intent)` → stream `PilotEvent` | `pilot.proto`: `PilotService.HandleIntent(HandleIntent_Request)` → stream `PilotEvent` |
| `robonix/sys/runtime/liaison` | same payloads as Pilot (entry layer) | same as Pilot contract | `liaison.proto`: `LiaisonService.HandleIntent(HandleIntent_Request)` → stream `PilotEvent` |
| `robonix/sys/runtime/executor` | `TaskGraph` → stream `TaskCallEvent` | `Stream(TaskGraph)` → … | `executor.proto`: `ExecutorService.Execute` → stream `TaskCallEvent` |
| `robonix/sys/model/vlm/chat` | Chat stream request → stream `ChatStreamEvent` | `Stream(ChatStream_Request)` → … | `vlm.proto`: `VlmService.ChatStream(ChatStream_Request)` → stream `ChatStreamEvent` |

Other RPCs on the same binary (e.g. `AbortSession`, `ListTools`, `Interrupt`) are **not** duplicated as separate contract files unless you add matching TOML + ids.

## Regenerate

From `rust/` (typical CI / local):

```bash
cargo run -p ridlc -- --lang proto \
  -I robonix-interfaces/lib \
  --contracts contracts \
  -o robonix-interfaces/robonix_proto
```

Iceoryx2 Python payloads (optional, separate output dir if desired):

```bash
cargo run -p ridlc -- --lang python \
  -I robonix-interfaces/lib \
  -o robonix-interfaces/robonix_iceoryx2_py
```

Do not hand-edit generated `robonix_proto/*.proto` or `*_iox2.py`; change `lib` IDL and/or contract TOML, then rerun `ridlc`.
